Monthly reconciliation check for the Robinhood Agentic account's (576391551) regime strategy (SPMO core + TQQQ/QLD satellite + BOXX cash; design and change log in STRATEGY.md Part I). Fires on the 1st of each month, 14:00 UTC. Purpose: catch a code bug, data-quality issue, missed rebalance or execution slippage before it compounds silently for months — this is NOT a strategy re-evaluation and does not authorize changing any live parameter on its own.

(Rewritten 2026-09-23: the previous version assumed a 75/25 SPMO/GLD core — gold was removed 2026-09-01 — a "$100/0.3%" trade threshold — removed 2026-09-01 — and raw target_weights(), which omits the vol target, fast re-entry, D gate and extension trim. The design has changed several times since inception, so a single backtest with today's code over the whole period is the wrong yardstick.)

1) LIVE SERIES. Reconstruct the account's time-weighted daily return since the last reconciliation (or since 2026-09-01 on the first run) from get_portfolio history / get_pnl_trade_history / get_equity_orders, folding in any deposits or withdrawals (check get_accounts and the transfer history; the owner funds episodically under the funding policy). While data/deposit_plan.json is active (staged $300k deposit from 2026-09-24), the unreleased reserve sits in BOXX outside the strategy: take it out of the live series (subtract its dollars and its BOXX return each session) so the comparison is investable account vs strategy, not a cash drag.

2) STRATEGY SERIES. Use data/live_nav_index.csv (drawdown_tracker): each row is the strategy's own daily return from the weights the live Routine targeted that session, with every overlay applied — i.e. what the design in force on that date should have earned. For any session missing a row, recompute it with paper-track/state.py's own functions exactly as the daily Routine does (compute_states, compute_fast_states, compute_extension_gaps, realized_vol_live, breadth_tracker.breadth_reading, a_trim_state — extension trim v2 since 2026-09-23 — and live_target_weights with all seven arguments; from 2026-10-08 on, live_target_weights_with_vixm with vx = vixm_state(...) replayed on the CBOE VIX/VIX3M history via vol_curve.history), using the design that was live on that date per STRATEGY.md's change log.

3) COMPARE, per calendar month and cumulatively since the last check:
   - Cumulative live vs strategy return. Normal sources of gap: 15:50 snapshot vs official close, the 5% L1 drift band (the account does not sit exactly on target between rebalances), fractional-share rounding, spreads. Flag as MATERIAL if the gap exceeds ~1.5 percentage points over a month, or ~3 pp cumulatively, unexplained by those.
   - Holdings vs target: for each session, compare actual weights (SPMO, TQQQ, QLD, XLU, VIXM, BOXX, idle cash) to the target for that session -- live_target_weights before 2026-10-08, live_target_weights_with_vixm (6 legs, vixm_state on the CBOE history) from 2026-10-08 on (while data/deposit_plan.json was active, the not-yet-released reserve parked in BOXX is outside the strategy: use deposit_plan.held_weights / reserve for that session's date, and check each tranche was traded within one session of its release). A regime change (effective state, HELD trim votes, the D gate switching, or from 2026-10-08 the VIXM allowed flag flipping) must be followed by a same-session rebalance; any session with L1 drift above 5% that was not rebalanced by the next session is MATERIAL (a Routine silently failed to trade).
   - Execution: paper-track/fill_quality.py summarize() — notional-weighted slippage vs the 4bp one-way cost model; lagged fills (session_lag=1) reported separately.

4) If nothing material: report a short one-paragraph confirmation (live vs strategy cumulative return, max holdings drift seen, slippage vs 4bp) and stop — do not touch any artifact for a routine clean check.

5) If something material: investigate before reporting — check the Routines' fire history (list_triggers; last_run on trig_01GGL83Q7cR8zDB9yPqnKurE daily, trig_01BasZybRAmmumVcNERAnKX7 weekly, trig_01Mm7fLoSeTacPcgrNAvVbmm watchdog), find the dates where holdings and target disagree, and report what diverged, by how much, and your best-guess cause. This is a diagnostic report to the owner, not an instruction to change anything — do not modify paper-track/state.py or any Routine based on this check alone.

If Robinhood MCP tools are unavailable, skip silently and let the next month's check try again — this is non-urgent housekeeping, not a trading action.
